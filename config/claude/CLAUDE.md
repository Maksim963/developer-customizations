## Use of subagents

Do the work in the main session when it can complete the task correctly and efficiently.

Use a subagent only when delegation improves the expected result. Delegation can improve the result through independent work, specialized capability, context isolation, or useful parallel execution.

Before you delegate, compare the expected benefit with the token use, duplicated work, coordination work, and loss of shared context.

Use only the delegation that the task requires. Give each subagent a distinct scope. Do not assign overlapping work unless independent verification is necessary.

Select the model, context size, and effort level for each subtask. Match these resources to the complexity, uncertainty, and risk of the subtask. Do not inherit an expensive parent configuration without a task-specific reason.

Use a less expensive model when it can complete the subtask reliably. Use a more expensive model only when it is likely to give a material improvement in correctness or judgment.

Follow project instructions that require a specialist or an independent review. Do not add other subagents unless they provide a separate benefit.

If you cannot identify a sufficient benefit from delegation, do not delegate.
